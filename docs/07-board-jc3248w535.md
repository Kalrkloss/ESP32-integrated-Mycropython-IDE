# Testboard JC3248W535 and how to talk to it (not the Zigbee stick!)

Status: 2026-10-10

## Board

| | |
|---|---|
| Module | Guition **JC3248W535** (ESP32-S3-WROOM-1) |
| Display | 3.5" IPS 320×480, **AXS15231B** over **QSPI** |
| Touch | AXS15231B, I2C (capacitive) |
| Flash / PSRAM | 16 MB flash / 8 MB PSRAM (OPI) |
| USB | USB-C, S3 **native USB-Serial-JTAG** (no CH340/CP210x) |
| Audio | the board's I2S DAC (details after the first test on the device) |
| Known quirks | QSPI panel only runs in **LVGL full refresh** (partial/direct render broken); **no hardware rotation** → 0°/180° in software; some batches ignore the window-address commands → always write full frames |

## Connection to the server — risk of mix-up!

Two Espressif devices hang on the dock. One is the **Zigbee coordinator**
(zigbee2mqtt, adapter `zboss`) — **do not touch, do not flash, do not reset**.

| Role | by-id | tty | USB path | Marker |
|---|---|---|---|---|
| **Zigbee stick (KEEP OFF)** | `usb-Espressif_USB_JTAG_serial_debug_unit_F0:F5:BD:03:09:5C-if00` | `/dev/ttyACM0` | `1-3` (directly on the root hub) | held open by `zigbee2mqtt.service` (lsof) |
| **Testboard JC3248W535** | `usb-Espressif_USB_JTAG_serial_debug_unit_98:3D:AE:E9:18:10-if00` | `/dev/ttyACM1` | `1-4.4.3` (dock port 3) | free, port is switchable |

Source of the mapping: `/dev/serial/by-id/`, `/dev/serial/by-path/`,
`/opt/zigbee2mqtt/data/configuration.yaml` (`serial.port`, `adapter: zboss`), `lsof`.

**Rule: always use the board's `by-id` path, never "the last" `/dev/ttyACM*`.**

## Reset / power cycle

The dock port is switchable, so a reset is possible without pulling the cable:

```bash
uhubctl -l 1-4.4 -p 3 -a cycle -d 2     # power-cycle of the board port (dock port 3)
```

The MAX! Cube hangs on the neighbour port (`1-4.4.4`) — cycling port 3 leaves it
untouched (state of the check: port 4 without a device).

## Flashing (planned)

```bash
python3 -m esptool --chip esp32s3 \
  --port /dev/serial/by-id/usb-Espressif_USB_JTAG_serial_debug_unit_98:3D:AE:E9:18:10-if00 \
  -b 460800 --before default_reset --after hard_reset write_flash \
  --flash_mode dio --flash_size 16MB --flash_freq 80m --erase-all \
  0x0 <firmware.bin>
```

## Firmware build (planned, lvgl_micropython)

```bash
python3 make.py esp32 BOARD=ESP32_GENERIC_S3 BOARD_VARIANT=SPIRAM_OCT \
  --flash-size=16 DISPLAY=axs15231b INDEV=axs15231 --ota
```

The drivers live in the binding under
`api_drivers/common_api_drivers/display/axs15231b/` and
`api_drivers/common_api_drivers/indev/axs15231.py` (checked in the repo
`lvgl-micropython/lvgl_micropython`).

## Why native USB-Serial-JTAG matters

On the S3, USB-OTG and USB-Serial-JTAG share one PHY. As long as we debug/flash over
USB-Serial-JTAG, **no USB host** is possible — and vice versa. For the later USB-audio
goal this means: debug over UART or an external PHY (SP5301/TUSB1106), see
[06-micropython-route.md](06-micropython-route.md).
