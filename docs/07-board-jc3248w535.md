# Testboard JC3248W535 und wie man es anspricht (nicht: das Zigbee-Stick!)

Stand: 2026-10-10

## Board

| | |
|---|---|
| Modul | Guition **JC3248W535** (ESP32-S3-WROOM-1) |
| Display | 3,5" IPS 320×480, **AXS15231B** über **QSPI** |
| Touch | AXS15231B, I2C (kapazitiv) |
| Flash / PSRAM | 16 MB Flash / 8 MB PSRAM (OPI) |
| USB | USB-C, **native USB-Serial-JTAG** des S3 (kein CH340/CP210x) |
| Audio | I2S-DAC des Boards (Details nach dem ersten Test am Gerät) |
| Bekannte Eigenheiten | QSPI-Panel läuft nur im **LVGL-Full-Refresh** (Partial/Direct-Render defekt); **keine Hardware-Rotation** → 0°/180° in Software; manche Chargen ignorieren die Window-Address-Kommandos → immer Full-Frame schreiben |

## Anschluss am Server — Verwechslungsgefahr!

Am Dock hängen **zwei** Espressif-Geräte. Das eine ist der **Zigbee-Koordinator**
(zigbee2mqtt, Adapter `zboss`) — **nicht anfassen, nicht flashen, nicht resetten**.

| Rolle | by-id | tty | USB-Pfad | Merkmal |
|---|---|---|---|---|
| **Zigbee-Stick (FINGER WEG)** | `usb-Espressif_USB_JTAG_serial_debug_unit_F0:F5:BD:03:09:5C-if00` | `/dev/ttyACM0` | `1-3` (direkt am Root-Hub) | wird von `zigbee2mqtt.service` offen gehalten (lsof) |
| **Testboard JC3248W535** | `usb-Espressif_USB_JTAG_serial_debug_unit_98:3D:AE:E9:18:10-if00` | `/dev/ttyACM1` | `1-4.4.3` (Dock-Port 3) | frei, Port ist schaltbar |

Quelle der Zuordnung: `/dev/serial/by-id/`, `/dev/serial/by-path/`,
`/opt/zigbee2mqtt/data/configuration.yaml` (`serial.port`, `adapter: zboss`), `lsof`.

**Regel: immer den `by-id`-Pfad des Boards verwenden, nie „den letzten" `/dev/ttyACM*`.**

## Reset / Stromzyklus

Der Dock-Port ist schaltbar, also ist ein Reset ohne Kabelziehen möglich:

```bash
uhubctl -l 1-4.4 -p 3 -a cycle -d 2     # Power-Cycle des Board-Ports (Dock-Port 3)
```

Der MAX!-Cube hängt am Nachbarport (`1-4.4.4`) — Port 3 zyklisch schalten lässt ihn
unberührt (Stand der Prüfung: Port 4 ohne Gerät).

## Flashen (geplant)

```bash
python3 -m esptool --chip esp32s3 \
  --port /dev/serial/by-id/usb-Espressif_USB_JTAG_serial_debug_unit_98:3D:AE:E9:18:10-if00 \
  -b 460800 --before default_reset --after hard_reset write_flash \
  --flash_mode dio --flash_size 16MB --flash_freq 80m --erase-all \
  0x0 <firmware.bin>
```

## Firmware-Build (geplant, lvgl_micropython)

```bash
python3 make.py esp32 BOARD=ESP32_GENERIC_S3 BOARD_VARIANT=SPIRAM_OCT \
  --flash-size=16 DISPLAY=axs15231b INDEV=axs15231 --ota
```

Die Treiber liegen im Binding unter
`api_drivers/common_api_drivers/display/axs15231b/` und
`api_drivers/common_api_drivers/indev/axs15231.py` (geprüft im Repo
`lvgl-micropython/lvgl_micropython`).

## Warum native USB-Serial-JTAG wichtig ist

USB-OTG und USB-Serial-JTAG teilen sich beim S3 einen PHY. Solange wir über
USB-Serial-JTAG debuggen/flashen, ist **kein USB-Host** möglich — und umgekehrt.
Für das spätere USB-Audio-Ziel heißt das: Debug über UART oder externe PHY
(SP5301/TUSB1106), siehe [06-micropython-route.md](06-micropython-route.md).
